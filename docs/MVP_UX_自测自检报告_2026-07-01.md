## 1. 本次评审依据

本次自测结合了以下项目资料：

- `README.md`：项目定位为 AI 机会情报系统，用户告诉 AI 想盯什么，系统搜索、筛选、评分、提醒和生成报告。
- `AGENTS.md`：当前最高优先级是自定义雷达 MVP 真实跑通，不破坏 V1.5 / V1.6，测试必须证明真实产品路径。
- `docs/superpowers/specs/2026-06-30-mvp-ux-rescue-design.md`：MVP 要从开发调试台收敛为客户能直接使用的机会雷达。
- `docs/superpowers/plans/2026-06-30-mvp-ux-rescue-implementation-plan.md`：Task 0~4.5 已用于搭建主路径；Task 5~8 暂未继续执行。

本次重点不是看代码字段是否存在，而是看客户是否能理解并完成：

```text
首页 → 输入/点模板 → 盯机会 → 画像确认 → 机会卡片 → Markdown 报告 → 保存长期雷达 → 我的雷达可查看
```

## 2. 浏览器自测路径

### 2.1 首页加载

检查结果：

- 页面标题：`ChancePing 盯机会`
- 可见导航：`首页 / 盯机会结果 / 我的雷达`
- 首页主文案：`告诉我你想盯什么机会`
- 副标题：`AI 会帮你找出本周值得行动的机会`
- 模板提示：`试试看这些例子`
- 主按钮：`盯机会`
- 控制台：无应用级 error / warning

结论：入口方向正确，已从“选择雷达”切到“告诉我需求”。

### 2.2 自由输入路径

输入：

```text
我是乒乓球选手，想了解国内外乒乓球比赛
```

页面成功进入画像确认卡，按钮为：

```text
确认，开始盯机会
我再改一下
```

但画像理解出现严重偏差：

```text
你是：自动化
你想盯：比赛
优先看：地区：全国；时间：及时获取 RPA 比赛信息并报名；排序：奖金、知名度
排除：已过期、需付费
```

问题：

- 用户说的是乒乓球选手，但画像识别成了“自动化”。
- 报告标题里出现了 `RPA`，与乒乓球需求明显不符。
- 这会让用户怀疑 AI 是否理解了自己。

结论：自由输入路径能跑通，但“需求理解质量”未达到 MVP 可用标准。

### 2.3 指定信号源

在画像卡中输入：

```text
https://www.ittf.com/
https://worldtabletennis.com/
中国乒协官网
```

结果页展示了来源检查：

```text
中国乒协官网 来源名称 0 条结果
ittf.com 未发现结果 0 条结果
worldtabletennis.com 未发现结果 0 条结果
```

优点：

- 来源被保留并展示，没有丢失。
- URL 能被解析为域名。

问题：

- Mock 模式下所有指定乒乓球来源均为 0 条结果，但机会卡片仍返回 AI 创新大赛。
- 用户会困惑：既然 ITTF/WTT 没有结果，为什么出现 AI 创新大赛？

结论：Source Hints 的保存和展示存在，但搜索结果与信号源检查之间缺少一致性。

### 2.4 机会卡片

实际返回机会：

```text
全国 AI 创新大赛 2026 官方介绍
全国 AI 创新大赛 2026 官方介绍
```

卡片字段顺序符合 Polish Sprint 要求：

```text
标题
为什么适合你
截止时间
建议动作
官方来源
```

严重问题：

- 乒乓球需求返回 AI 创新大赛，机会类型错位。
- 两张机会标题重复。
- 截止时间均为 `未明确`。
- 建议动作是 `了解即可`，不够行动化。
- 官方来源是 `competition.example.com` 和 `hackathon.example.com`，不可作为 MVP 正式体验。

结论：前端卡片结构可用，但机会数据质量当前不达标。

### 2.5 Markdown 报告

报告可展开，包含：

- `## 0. 本轮总判断`
- `## 1. 雷达画像`
- `## 2. 本轮机会总表`
- `## 7. 来源索引`

复制 Markdown 成功，剪贴板内容包含 `## 1. 雷达画像`。

问题：

- 报告标题出现 `盯 RPA 相关的比赛机会`，与用户输入冲突。
- 报告摘要只是取了机会匹配理由，不像真正的判断摘要。
- 报告中仍含 `example.com` 假链接。
- 推荐机会重复。

结论：报告结构已经接近 MVP 模板，但内容质量依赖错误画像和假 mock 数据，暂不能算可交付体验。

### 2.6 保存长期雷达

在当前已有 1 个自定义雷达时，点击保存返回：

## 4. 问题分级

### P0：必须先修，否则 MVP 不可信

#### P0-1 自由输入画像理解错误

用户输入乒乓球，系统识别成自动化 / RPA。

影响：

- 破坏“AI 理解你”的第一信任点。
- 后续机会和报告都跟着跑偏。

建议：

- Mock 模式下先加入领域关键词兜底映射。
- `乒乓球 / WTT / ITTF / 中国乒协 / 公开赛` 应识别为体育赛事 / 乒乓球选手画像。
- 自由输入生成的 `profile` 应优先使用用户原文中的强信号，不要套用默认 RPA/AI 赛事模板。

#### P0-2 Mock 结果与画像错域

乒乓球路径返回 AI 创新大赛。

影响：

- 用户无法相信“盯机会”真的按画像工作。
- 示例模板失去教育意义。

建议：

- 在 Mock 搜索中按关键词/模板返回领域相关 mock 数据。
- 至少补齐 4 类 MVP 示例的 mock 数据：
  - AI 赛事
  - 创业比赛申报
  - 奥数竞赛
  - 乒乓球赛事
- 每类至少 2 条高质量机会卡片。

#### P0-3 假链接仍出现在核心路径

机会来源仍为：

```text
competition.example.com
hackathon.example.com
```

影响：

- 用户点击无法访问。
- 与“官方来源”文案冲突。

建议：

- 立即移除 MVP 主路径中的 `example.com`。
- Mock 数据可以使用真实官网首页或公开列表页。
- 如果无法提供真实详情页，应显示“演示来源”，不要标成官方来源。

#### P0-4 报告摘要不是判断摘要

当前摘要基本是第一条机会的匹配理由。

影响：

- 用户看不到“本轮是否值得行动”的结论。

建议：

- 摘要区固定展示：
  - 本轮发现 N 条机会
  - 最推荐 1 条
  - 本周建议动作
  - 是否建议保存长期监控

#### P0-5 免费配额阻塞没有可操作闭环

已有 1 个雷达时，保存长期雷达失败，只显示 toast。

影响：

- 用户到了最关键转化动作，却不知道下一步怎么做。

建议：

- 在保存失败时展示内联卡片：
  - 当前已达免费版 3/3
  - 显示现有自定义雷达
  - 操作：归档旧雷达并保存当前雷达
  - 操作：返回我的雷达管理

### P1：基础 MVP 应尽快修

#### P1-1 我的雷达仍显示技术字段

列表和详情页展示 provider、RadarSpec、评分规则、Radar ID、ChanceScore。

建议：

- 用户视角只展示：画像摘要、最近机会、最近报告、运行历史。
- 技术字段折叠到“高级调试”，默认隐藏。

#### P1-2 机会卡行动性不足

当前建议动作多为 `了解即可`。

建议：

- Mock 卡片补齐更具体动作：
  - 打开官网确认报名资格
  - 记录截止日期
  - 准备报名材料
  - 收藏并下次继续监控

#### P1-3 机会重复

两条机会标题完全相同。

建议：

- Mock 数据层去重。
- UI 层可在同标题时合并来源或标记重复。

#### P1-4 来源检查与机会来源割裂

ITTF/WTT 均显示未发现结果，但机会却来自 AI 大赛。

建议：

- 当用户指定来源时，机会卡应优先展示来自指定来源或同领域来源的结果。
- 如果指定来源无结果，报告应解释“本轮未从指定来源发现机会，以下为扩展搜索结果”。

### P2：体验润色

#### P2-1 移动端附件按钮位置弱

建议：

- 移动端把附件按钮放到输入框左下或工具条内。

#### P2-2 保存按钮在结果页太靠上

建议：

- 首次结果页可以把保存 CTA 放在报告摘要后，或者顶部保留轻量 CTA，底部再出现强 CTA。

#### P2-3 空结果页未实测

当前 Mock 管道总会返回机会，空结果状态虽然有代码，但未通过真实场景触发。

建议：

- 增加一个会稳定返回空结果的测试 spec/mock 场景。

## 5. 建议修改计划

在进入 Task 5~8 前，建议先做一个小的基础修复包：

```text
MVP Foundation Fix Pack
目标：让当前主路径不仅能跑通，而且结果可信、链接可点、保存可闭环。
```

### Step A：修 Mock 领域一致性

范围：

- `src/search` mock / recorded data 逻辑
- demo mock 数据
- `web/mvp-templates.js`

验收：

```text
乒乓球输入 → 画像为乒乓球选手 → 机会为乒乓球/WTT/ITTF/中国乒协相关
AI 赛事模板 → 机会为 AI 赛事
创业比赛模板 → 机会为创业/申报
奥数模板 → 机会为数学竞赛
```

输出：

- 不再出现错域机会。
- 不再出现重复标题。

### Step B：移除主路径假链接

范围：

- 所有 MVP 主路径 mock 机会链接
- 新增或启用 `verify-mock-links`

验收：

```text
rg "example.com|competition.example.com|hackathon.example.com" src web docs scripts
```

主路径机会数据不能含假链接。

### Step C：修自由输入画像兜底

范围：

- Mock 画像生成器
- 画像确认卡 profile 映射

验收：

```text
我是乒乓球选手，想了解国内外乒乓球比赛
```

必须展示：

```text
你是：乒乓球选手
你想盯：乒乓球比赛 / 公开赛 / WTT / ITTF
优先看：可报名、权威来源、适合个人参赛
排除：培训广告、旧新闻、已截止
```

### Step D：修报告摘要

范围：

- `web/watch-result.js`

验收：

摘要必须包含：

```text
本轮发现 N 条机会
最推荐：{机会标题}
本周建议动作：{动作}
建议：保存为长期雷达 / 继续监控
```

不能只是复制 `match_reason`。

### Step E：保存配额阻塞闭环

范围：

- `web/watch-result.js`
- 可能需要读取 `/api/radars` 和归档 API

验收：

当免费版 3/3 时，点击保存后出现：

```text
已达到免费版 3 个长期雷达
当前雷达：{旧雷达名}
按钮：归档旧雷达并保存当前雷达
按钮：去我的雷达管理
```

### Step F：补真实浏览器验收脚本

范围：

- `scripts/verify-mvp-browser-smoke.ts`

验收增加内容：

- 检查乒乓球路径不能出现 `AI 创新大赛`。
- 检查不能出现 `example.com`。
- 检查画像里不能出现 `自动化` / `RPA`。
- 检查报告摘要包含“本轮发现”。
- 检查免费配额阻塞时有可行动 UI。

## 6. Task 5~8 的进入条件

建议不要马上进入 Task 5~8。先满足以下条件：

1. 乒乓球自由输入路径返回乒乓球相关机会。
2. 4 个模板都返回对应领域机会。
3. MVP 主路径不再出现 `example.com` 假链接。
4. 报告摘要像判断报告，而不是 raw match reason。
5. 保存配额满时有明确处理动作。
6. 浏览器 smoke 能验证上述质量要求。

满足后再进入：

- Task 5：简化我的雷达。
- Task 6：系统性清理 mock 链接。如果 Step B 已完成，Task 6 可以变成补全验收与全量扫尾。
- Task 7：本地安全加载 `api.env`。
- Task 8：Jason 明确允许后再跑 live API。
