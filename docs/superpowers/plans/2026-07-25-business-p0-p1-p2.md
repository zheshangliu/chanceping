# ChancePing Business P0-P1-P2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Complete the Business Radar roadmap in order: P0 credibility and matching, P1 retention/action workflows, then P2 multi-company and operations foundations.

**Architecture:** Keep the existing Hono + TypeScript API and static Business frontend. Add additive, file-backed Business modules with deterministic fixtures and explicit public contracts; no main-branch changes and no destructive migration. P0 owns authoritative opportunity governance and match output, P1 owns user-scoped saved workflows, and P2 owns profile/organization boundaries and review operations.

**Tech Stack:** TypeScript, Hono, Node file-backed stores, static HTML/CSS/JS, `tsx` verification scripts.

## Global Constraints

- Work only on `rescue/mvp-codex`; never modify `main`.
- Preserve existing V1.5/V1.6 and Business public API contracts; additions must be backward compatible.
- Current opportunity data must never expose historical or candidate-discovery facts in the default public flow.
- `UNKNOWN` eligibility is not `PASS`; every score must expose reasons, unknowns, preparation cost, and local relevance.
- Every phase ends with fresh typecheck, build, focused verification, and relevant regression checks.
- Production deployment is only after all phase gates pass and a release manifest is generated.
