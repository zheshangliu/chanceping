# ChancePing MVP UX Rescue Design

## 1. 背景

ChancePing / 盯机会 当前已经有雷达、搜索、机会库、报告、定时、编辑器等能力，但这些能力被拆成了太多工程页面。普通客户打开后需要先理解“雷达类型、搜索页、机会库、报告页、编辑器”等概念，才能猜到产品怎么用。

Jason 的反馈说明：当前问题不是单点 bug，而是 MVP 信息架构没有围绕客户的真实任务来组织。

客户真正想完成的任务是：

```text
我告诉系统我想盯什么机会，或者点一个示例，系统马上帮我盯一下，返回本周可行动机会和报告。
```

## 2. MVP 目标

本轮 MVP 设计目标是把产品从“开发调试台”收敛为“客户能直接使用的机会雷达”。

成功标准：

1. 用户无需理解雷达类型，也能点击示例或输入需求。
2. 用户点击一个主按钮：`盯一下`。
3. 系统直接返回机会卡片和 Markdown 报告。
4. 用户可以把这次结果保存为长期雷达。
5. 用户在“我的雷达”中能看到历史运行、机会和报告。
6. 高级编辑器、provider、原始 spec、Watch Rules 不出现在普通客户主路径。

## 3. 核心产品原则

### 3.1 以终为始

用户最终要的不是“配置雷达”，而是：

```text
我有没有错过值得行动的机会？
```

因此首页必须直接让用户看到结果，而不是先要求用户理解配置。

### 3.2 示例不是雷达选择器

首页的 AI 赛事、政策申报、文创非遗、乒乓球赛事等入口是示例模板，不是必选分类。

它们的作用是让新用户快速明白：

```text
原来我可以这样让 ChancePing 帮我盯机会。
```

### 3.3 结果优先，保存其次

用户第一次点击 `盯一下` 时，不应该先被迫创建长期雷达。系统应先给结果，用户觉得有用后再点击“保存为长期雷达”。

### 3.4 主路径少页面

MVP 主导航收敛为 3 个入口：

1. 首页
2. 盯机会结果
3. 我的雷达

搜索、机会库、报告、编辑器保留代码能力，但从普通客户主导航隐藏或合并。

## 4. 新信息架构

### 4.1 首页

首页职责：

- 让用户输入“我想盯什么”
- 展示 3 到 4 个可点击示例
- 对自由输入先生成“雷达画像草案”，再让用户确认
- 对示例模板使用预置雷达画像，可直接 `盯一下`

首页不再展示：

- “选择雷达”
- AI 赛事 / 政策申报 / 文创非遗作为必选类型
- 技术化的雷达切换控件

首页建议文案：

```text
告诉我你想盯什么机会，什么比赛，什么信息都可以。
```

输入框 placeholder：

```text
例如：我是乒乓球选手，想盯国内外比赛报名机会
```

主按钮：

```text
盯一下
```

示例模板：

1. AI 赛事：追踪 AI 创作比赛、AI 游戏比赛、模型厂商黑客松、带奖金或曝光价值的赛事。
2. 创业比赛申报：帮客户追踪创业比赛、创新创业大赛、项目申报、政府补贴。
3. 奥数竞赛：追踪国内外数学竞赛、报名时间、年龄组、赛区通知。
4. 乒乓球赛事：追踪国内外乒乓球比赛、WTT/ITTF、公开赛、报名窗口。

自由输入规则：

- 自由输入不是一次性搜索 query。
- 系统必须先把自由输入转成可复用的“雷达画像”。
- 用户确认画像后，画像固定为该雷达的长期搜索模型。
- 以后用户每次运行该雷达，都沿用这个画像，而不是重新询问需求。

### 4.2 雷达画像确认

自由输入路径必须经过画像确认步骤。

```text
用户自由输入
→ AI 生成雷达画像草案
→ 用户确认 / 微调
→ 保存为我的雷达
→ 运行该雷达
→ 输出机会卡片和 Markdown 报告
```

雷达画像至少包含：

- 用户身份：例如乒乓球选手、财税公司、奥数学生家长、猎头顾问。
- 关注机会：赛事、申报、客户线索、岗位、活动、奖项等。
- 地域范围：中国、海外、指定城市或指定赛区。
- 时间范围：本周、本月、未来 30 天、可报名中。
- 机会类型：报名、申报、比赛、BD 线索、岗位、展会等。
- 指定信号源/搜索源：客户希望雷达优先检查的网址、官网、平台或来源名称。
- 排除内容：广告、旧新闻、已截止、低权威来源、不匹配年龄组。
- 排序偏好：截止近、权威来源、高奖金、高曝光、高适配度。
- 输出偏好：机会卡片、Markdown 日报、周报、BD 作战版等。

画像确认页不应像生硬问卷，而应像 AI 助手的理解卡片：

```text
我理解你想建立这样的雷达：

你是：乒乓球选手
你想盯：国内外近期可报名的乒乓球比赛
优先看：报名未截止、权威赛事、适合个人参赛
优先检查：ITTF 官网、WTT 官网、中国乒协官网
排除：旧新闻、培训广告、不可报名的资讯

是否按这个画像创建雷达？
```

MVP 阶段只允许追问 1 到 3 个关键问题。能推断时不要追问，避免把流程做成复杂表单。

示例模板路径可以跳过确认，因为模板已经内置画像。用户也可以在保存前点击“查看/调整画像”。

### 4.3 客户自定义信号源

客户可以在创建或调整雷达画像时补充搜索源。

MVP 支持两类输入：

1. URL 来源：例如 `https://www.ittf.com/`、`https://worldtabletennis.com/`。
2. 来源名称：例如“中国乒协官网”“深圳市科技创新局”“某某创业大赛官网”。

产品规则：

- URL 来源保存到 `spec.source_strategy.user_supplied_sources`。
- 来源名称保存到 `spec.source_strategy.manual_sources`，并作为搜索 query 的来源提示。
- 运行雷达时，系统先按画像做常规搜索，再对 URL 来源做 `site:domain` 或 provider site filter 补充搜索。
- 用户指定来源是“优先检查”，不是“只搜索这些来源”。除非后续高级模式另行支持。
- 如果来源无法访问或没有返回结果，报告要显示为“待复核来源”，不能假装已搜索成功。
- 来源管理在 MVP 阶段只做轻量输入与保存，不做完整来源库后台。

画像确认卡中的展示建议：

```text
指定信号源（可选）
每行一个官网、网址或平台名称

https://www.ittf.com/
https://worldtabletennis.com/
中国乒协官网
```

### 4.4 盯机会结果页

结果页合并当前“搜索页、机会库、报告页”的核心客户价值。

用户点击 `盯一下` 后，系统基于已确认的雷达画像运行搜索，页面展示：

1. 本次雷达画像摘要
2. 本轮重点检查来源
3. 搜索状态
4. 机会卡片
5. Markdown 报告
6. 保存或更新该长期雷达

机会卡片必须展示：

- 标题
- 为什么适合我
- 截止日期
- 来源链接
- 可信程度或来源类型
- 行动建议

结果页不展示：

- provider 调试信息
- 原始 spec
- 后台评分细节
- 过多技术字段

如果没有机会，页面不能只显示空白，而要解释：

```text
这次没有找到足够匹配的机会。你可以放宽地区、扩大关键词，或保存为雷达持续盯。
```

### 4.5 我的雷达

我的雷达职责是长期管理，不是创建调试台。

展示字段：

- 雷达名称
- 最近一次运行时间
- 最近机会数量
- 最近报告
- 状态：运行中 / 已暂停
- 操作：重新盯一下、查看历史、暂停、删除

隐藏字段：

- Provider
- RadarSpec 原始字段
- Watch Rules
- 调试统计

雷达详情页展示：

- 需求摘要
- 指定信号源
- 最近机会
- 历史报告
- 运行历史

### 4.6 高级功能

以下能力暂时从主导航隐藏：

- 搜索页
- 机会库独立页
- 报告独立页
- 编辑器
- Watch Rules 编辑器

保留原因：

- 开发调试仍可能需要
- 后续高级用户或内部运营可重新开放

隐藏方式：

- 不从普通导航显示
- 可通过 URL 或高级开关访问

## 5. 推荐数据流

### 5.1 自由输入建立雷达画像

```text
用户自由输入
→ POST /api/radars/generate
→ 返回 suggestedName + spec + profileSummary + clarificationQuestions?
→ 前端展示画像确认卡
→ 用户确认或微调画像 + 指定信号源
→ 将 URL 来源写入 spec.source_strategy.user_supplied_sources
→ 将来源名称写入 spec.source_strategy.manual_sources
→ POST /api/radars
→ POST /api/radars/:id/activate
→ POST /api/radars/:id/run
→ 结果页展示机会和 Markdown 报告
```

自由输入路径会创建自定义雷达，因此应消耗自定义雷达配额。MVP 可先不做复杂计费，但数据模型上应按长期雷达处理。

### 5.2 示例模板直接运行

```text
用户点击示例模板
→ 前端加载预置 spec/profile
→ 用户点击盯一下
→ POST /api/search with preset spec + source_strategy
→ POST /api/reports/generate with opportunityCards + profile
→ 结果页展示机会和 Markdown 报告
→ 用户可选择保存为我的雷达
```

示例模板路径的目标是教育用户“原来可以这样用”。因此可以先不消耗自定义雷达配额，直到用户点击保存。

### 5.3 保存为长期雷达

```text
用户点击保存为长期雷达
→ POST /api/radars
→ POST /api/radars/:id/activate
→ 可选：POST /api/radars/:id/run
→ 我的雷达显示该雷达
```

这条路径消耗自定义雷达配额。

### 5.4 我的雷达重新运行

```text
用户在我的雷达点击重新盯一下
→ POST /api/radars/:id/run
→ 机会入库并绑定 radarIds
→ 搜索层读取 spec.source_strategy.user_supplied_sources
→ POST /api/reports/generate with radar_id + run_id + profile
→ RadarRun.reportId 回写
```

## 6. Markdown 报告模板

ChancePing 的报告不是普通搜索结果，而是基于雷达画像的判断报告。

MVP 标准 Markdown 模板：

```md
# 机会雷达报告｜{雷达名称}｜{日期}

## 0. 本轮总判断
- 本轮是否发现值得行动的机会
- 最推荐关注的 1-3 个机会
- 本周最重要动作
- 是否建议继续监控

## 1. 雷达画像
- 用户身份：
- 关注机会：
- 地域范围：
- 时间范围：
- 指定信号源：
- 排除内容：
- 排序偏好：

## 2. 本轮机会总表
| 等级 | 机会名称 | 截止时间 | 适配度 | 建议动作 | 来源 |
|---|---|---|---|---|---|

## 3. 重点机会详解
### 机会 1：{名称}
#### 基本信息
#### 为什么适合你
#### 推荐动作
#### 风险提醒
#### 官方来源

## 4. 暂不推荐 / 观察池
- 不推荐原因
- 后续是否继续监控

## 5. 本周行动清单
- 今天要做
- 本周要做
- 后续准备

## 6. 下一轮继续监控重点
- 关键词
- 来源网站
- 时间窗口

## 7. 来源索引
- 本轮重点检查来源
- 官方链接 1
- 官方链接 2
- 待复核来源
```

页面展示应比 Markdown 更轻：

- 首屏展示总判断、机会卡片、本周行动。
- Markdown 展示完整机会详解、风险提醒、来源索引。
- 高级用户后续可选择“作战版周报”，但不作为 MVP 默认输出。

每条机会必须有真实来源链接。来源无法访问时，不应作为正式机会展示，只能放入“待复核线索”或被过滤。

客户指定的信号源也必须在报告中透明展示：

- 已检查且返回结果的来源：展示在“本轮重点检查来源”。
- 未返回结果或抓取失败的来源：展示在“待复核来源”。
- 不能把客户提供的网址改写成不存在的假链接。

## 7. API 与真实模式

Jason 已在根目录放置 `api.env`。该文件包含真实 API Key，应只用于本地 live 测试，不能提交到 GitHub。

需要支持：

- `DATA_MODE=live`
- `LLM_MODE=live`
- `SERPER_API_KEY`
- `DEEPSEEK_API_KEY`
- `DASHSCOPE_API_KEY`
- `ZAI_API_KEY`
- `JINA_READER_API_KEY`
- 代理变量：`HTTP_PROXY` / `HTTPS_PROXY`

MVP live 验收场景：

1. AI 赛事
2. 乒乓球赛事
3. 创业比赛申报

每个场景至少要求：

- 搜索返回真实可访问链接
- 至少 1 条机会可打开
- 报告包含机会标题
- 页面刷新后仍能看到结果

## 8. 关键风险

### 8.1 Mock 链接不可访问

当前机会库出现 `competition.example.com` 这类假链接，用户点击后无法访问。MVP Mock 数据也必须用可访问链接，或者明确标记为演示数据。

### 8.2 首页误导用户

如果首页继续出现“选择雷达”，用户会误以为必须先懂雷达类型。必须改成模板示例和自由输入。

### 8.3 画像确认生硬

画像确认不能做成固定问卷。它应该是 AI 对用户需求的理解卡片，只在缺少关键约束时追问 1 到 3 个问题。

### 8.4 页面功能重叠

机会库和报告在普通客户视角重复。结果页合并后，机会卡片是事实层，报告是总结层。

### 8.5 客户指定来源不可访问

客户输入的网址可能过期、拼写错误、禁止抓取或不返回搜索结果。MVP 不做复杂健康检测，但必须做到：

- 保存原始来源。
- 搜索失败时记录状态。
- 报告里标记为“待复核来源”。
- 不把失败来源包装成有效机会。

## 9. 非目标

本轮不做：

- 雷达市场
- 团队协作
- 付费体系
- V1.7 来源透明完整链路
- 复杂权限系统
- 完整 SaaS 后台
- 大规模品牌视觉重构
- 完整信号源管理后台
- 来源健康监控和自动订阅系统
- RSS/爬虫调度平台

## 10. 验收标准

### 10.1 客户路径验收

1. 打开首页。
2. 点击“AI 赛事”示例。
3. 点击 `盯一下`。
4. 进入结果页。
5. 看到至少 1 条机会卡片。
6. 看到 Markdown 报告。
7. 点击“保存为长期雷达”。
8. 在“我的雷达”看到该雷达。
9. 点击重新盯一下。
10. 刷新页面后机会和报告仍在。

自由输入路径还必须通过：

1. 输入“我是乒乓球选手，想了解国内外乒乓球比赛”。
2. 生成雷达画像确认卡。
3. 在画像确认卡中添加 2 个 URL 来源和 1 个来源名称。
4. 确认画像并保存为雷达。
5. 运行该雷达。
6. 报告中包含“雷达画像”“指定信号源”和真实来源索引。
7. 再次运行同一个雷达时沿用同一画像和同一批信号源，不重新询问需求。

### 10.2 技术验收

必须通过：

```bash
tsc --noEmit
tsx scripts/verify-v1.5-e2e.ts
tsx scripts/verify-task-v1.5-04-ui.ts
tsx scripts/verify-task038.ts
tsx scripts/verify-task034.ts
```

如果当前环境有 npm，也应通过：

```bash
npm run verify:v15:e2e
npm run verify:v16
npm run verify:all
```

## 11. 建议实施顺序

1. 保护 `api.env`，确认真实 API 配置只在本地使用。
2. 改首页：示例模板 + 自由输入 + `盯一下`。
3. 增加雷达画像确认：自由输入先建模，确认后固定为长期雷达。
4. 增加客户自定义信号源：URL 来源进入 `user_supplied_sources`，名称来源进入 `manual_sources`。
5. 新建或改造结果页：画像摘要 + 本轮检查来源 + 机会 + Markdown 报告 + 保存雷达。
6. 固化 Markdown 报告模板。
7. 简化我的雷达页。
8. 隐藏搜索/机会库/报告/编辑器主导航。
9. 修 Mock 链接。
10. 接入 live 模式验收。
