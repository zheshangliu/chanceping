## 2. 产品路线

### Phase 1：固定 AI 赛事雷达样板间

目标：

- `AI 赛事雷达` 固定在首页 / 左侧雷达列表第一位。
- 它是样板间，不是用户个人雷达。
- 默认只读，用户不能直接修改样板间。
- 用户可以点击 `发送固定提示词`，系统整理成 `AI 赛事雷达 V1.0`。
- 用户点击 `确认，按 V1.0 盯一次` 后，系统自动搜索并生成机会卡和报告。
- 提供 `复制为我的雷达`，复制后才进入用户可编辑体验。

验收：

- 新用户打开页面能看到左侧 `AI 赛事雷达`。
- 点击后出现固定提示词。
- 不需要用户手写需求，也能完成：

```text
固定提示词 -> V1.0 雷达 -> 确认 -> 搜索 -> opportunityCards -> Markdown 报告
```

- 样板间原件不会被用户修改。
- 复制副本不影响原始样板间。

### Phase 2：主控台 UI polish

目标：

- 当前主控台不再像工程后台。
- 聊天窗口、左侧雷达列表、机会卡、报告弹窗、进度提示都要更适合演示。
- 不扩展新业务功能，只做当前样板间体验 polish。

重点：

- 顶部：全局 banner / header 保持连续，不因进入 Hero Demo 消失。
- 左侧：固定样板间 + 我的雷达入口，支持类似 ChatGPT 首页的展开 / 折叠。
- 中间：更宽的聊天工作台，作为主舞台。
- 右侧或弹窗：雷达画像、机会卡、Markdown 报告。
- 机会卡文案从工程解释改成顾问式解释：

```text
为什么值得看
适合谁
下一步动作
哪些字段待复核
官方入口 / 线索来源
```

全局 banner / header 要求：

- 首页红框所示区域视为全局 banner / header，不是只属于首页的装饰。
- 用户进入 `AI 赛事雷达` Hero Demo 后，banner 不能直接消失。
- banner 至少持续展示：ChancePing / 盯机会品牌、运行环境或状态、主要导航入口、主题 / 在线状态。
- 进入 Hero Demo 后可以压缩 banner 高度，避免占用过多首屏空间，但品牌和状态要保持可见。
- Demo 内的会话标题栏不能完全替代全局 banner；如果保留会话标题栏，应放在 banner 下方作为当前雷达上下文。
- 从首页到 Hero Demo 的视觉切换要连续，不能让用户感觉进入了另一个后台页面。
- 主控台统一使用白天模式，不再提供太阳 / 月亮的明暗主题切换。
- 右上角原主题切换位置后续可改为 `中文 / English` 语言切换。
- 中英文切换需要作为完整前端 i18n 做，不要只做一个按钮但页面文案仍半中半英。
- 语言切换不作为 AI 赛事 Hero Demo 固定前的阻塞项，可放到 Phase 2 UI polish 后半段或后续国际化任务。

左侧边栏要求：

- 展开态：宽度约 250-280px，顶部有 ChancePing / 盯机会标识和折叠按钮。
- 折叠态：收成约 52-64px 的图标栏，只保留核心入口图标。
- 折叠按钮放在顶部，行为和参考图中的 ChatGPT 侧边栏一致。
- `AI 赛事雷达` 固定为左侧第一个样板间入口，视觉上要明显区别于普通用户雷达。
- `我的雷达` 放在样板间下方，承接后续最多 3 个体验雷达。
- 折叠状态下仍能快速进入 `AI 赛事雷达`，不要让样板间入口消失。

聊天工作台要求：

- 首页默认视图以聊天输入为中心，不要做成后台管理台。
- 主聊天区在桌面端居中，宽度建议约 820-960px，比当前更开阔。
- 输入框采用横向长条，保留一键发送固定提示词 / 确认 V1.0 / 运行一次等主动作。
- 首屏保持干净，只露出必要入口，不堆叠过多工程状态和调试信息。
- 移动端优先保证输入框、样板间入口、机会卡列表可用，左侧边栏可转为抽屉。

我的雷达列表要求：

- 列表卡片不展示 `succeeded`、`failed` 等工程 raw 状态。
- 不展示 `激活`、`暂停`、`停止`、`运行中` 等生命周期状态。
- 如需展示提示，只用结果型中文提示，例如 `最近已更新`、`需要处理`。
- 上次运行时间可以保留，但弱化展示，不作为卡片视觉重点。
- 每个雷达卡片只保留三个操作：`编辑雷达`、`查看机会和报告`、`删除雷达`。
- `查看机会和报告` 应跳转到与首次搜索后 `查看机会卡` 相同的结果页。
- `再次盯机会` 不在列表卡片中展示，避免按钮过多。
- 如果需要手动再跑一次，放到雷达详情页、机会结果页或报告页中的主操作区。
- 删除雷达属于危险操作，视觉上应弱化或二次确认，不和主要操作混在一起。

雷达详情页操作文案要求：

- 不直接展示 `激活`、`归档`、`succeeded` 等偏工程 / 后台词。
- 不再设计 `激活`、`停止`、`暂停`、`恢复` 等雷达生命周期按钮或状态。
- `再次盯机会` 可以保留在详情页或结果页主操作区，用于手动再跑一次。
- `编辑` 改成 `编辑雷达`，保持和列表页一致。
- `归档` 统一改为 `删除雷达`。
- `删除雷达` 必须二次确认，确认弹窗要明确告诉用户删除影响。
- 删除动作不要和主要操作混在一起，使用危险操作样式。
- 详情页顶部操作最多保留 2 个主操作 + 1 个更多菜单，避免一排按钮过多。

已入库机会展示要求：

- `已入库机会` 使用机会卡片形式展示，不使用数据库记录样式。
- 展示范围覆盖该雷达从第一次运行到最近一次运行捕获过的机会。
- 机会卡复用搜索结果页的机会卡组件，保持标题、标签、为什么值得看、截止时间、建议动作、官方入口 / 待复核来源等字段一致。
- 桌面端可使用卡片网格或时间流卡片，一行 2-3 张；移动端一行 1 张。
- 默认按最近发现 / 最近更新排序，也可以标记 `首次发现`、`最近发现`。
- 同一机会跨多次搜索重复出现时应合并展示，不重复堆叠；可显示 `已多次发现` 或 `最近再次发现`。
- 不展示 `radarId`、`入库 Key`、`report id`、`succeeded` 等调试字段。
- `ChanceScore` 不作为裸字段展示，可转成用户能理解的 `推荐度` 或 `值得关注`。
- 不单独展示 `运行历史` 表格。
- 历史辅助信息只保留 `历史报告` 一个模块，放在机会卡片之后，或默认折叠。
- `历史报告` 展示过去每次搜索后生成的报告，可包含标题、时间、机会数、查看 / 下载操作。
- `历史报告` 模块不展示 `生成 Markdown 报告` 按钮。
- 如果需要重新搜索并生成新报告，统一使用 `再次盯机会` 入口，不用 `生成 Markdown 报告` 表达。

搜索结果页布局要求：

- 结果页是统一页面：首次搜索后点击 `查看机会卡`，以及 `我的雷达` 列表点击 `查看机会和报告`，都进入同一个页面 / 组件。
- 不额外做一个“历史查看机会和报告”页面，避免页面过多。
- 如果从 `我的雷达` 进入，默认展示该雷达最近一次运行的机会卡和报告摘要。
- 顶部操作区只保留必要按钮，避免重复语义。
- 主按钮保留 `保存为长期雷达，之后持续盯`。
- 修改类按钮只保留一个次级按钮，推荐文案为 `调整雷达画像`。
- `调整画像` 与 `这些结果不对，修改雷达` 视为同一入口，不要同时出现。
- 如果用户认为结果不对，也通过 `调整雷达画像` 进入修改流程。
- 点击 `查看机会卡` 后，结果页优先展示机会卡，不做“机会卡左侧、报告摘要右侧”的左右双栏。
- 机会卡采用横向响应式网格：桌面端一行 3-4 张，普通宽度一行 2-3 张，移动端一行 1 张。
- 一个机会就是一张独立卡片，不再把多张机会卡包在一个大的“机会卡片”容器里。
- 每张机会卡展示：标题、状态 / 标签、为什么值得看、截止时间、建议动作、官方入口或待复核来源。
- 报告摘要放在机会卡网格下方，作为全宽模块展示。
- `查看完整 Markdown 报告` / `复制 Markdown` 等操作放在报告摘要模块内。
- 信息层级顺序为：雷达说明和操作按钮 -> 机会卡网格 -> 报告摘要 -> 完整 Markdown。
- 该布局也作为后续 `/ai-events` 公开页的基础视觉方向。

### Phase 3：AI 赛事情报雷达公开页面

目标：

- 新增一个对外展示页，第一版先放在当前项目：

```text
/ai-events
```

- 后续上阿里云后，可以抽成：

```text
https://chanceping.com/ai-events
```

或：

```text
https://aievents.chanceping.com
```

- 页面第一版只展示机会卡网格，不做复杂排行榜和分级系统。
- 不对外展示 S/A/B/C 等内部评分。

对外标签使用：

```text
开放报名
即将截止
官方入口
新增收录
平台活动
开发者挑战
创业扶持
往期归档
待复核
```

机会卡字段建议：

- 封面图 / banner。
- 平台：Devpost / TRAE / Kaggle / DoraHacks / Lablab 等。
- 状态：报名中 / 即将截止 / 待复核 / 已归档。
- 标题。
- 标签：AI Agent、AIGC、云资源、Hackathon、线上等。
- 截止时间。
- 奖金 / 云资源 / 展示机会。
- 官方入口按钮。

技术边界：

- 先在当前 Hono 项目中新增页面和路由。
- 读取现有机会卡 / 报告 / RadarRun 数据。
- 后续独立静态站通过公开 API 读取服务器数据。
- 公开 API 只返回清洗后的展示字段，不暴露内部评分、调试字段、API key、raw logs。
