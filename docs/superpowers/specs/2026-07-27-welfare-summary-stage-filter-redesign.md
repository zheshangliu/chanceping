# 企业福利商机雷达：统计摘要与阶段筛选重排设计

## 目标

压缩机会列表上方的信息密度，消除重复导航，同时保留当前机会、前置信号、历史续采和待核验线索的完整访问能力。

## 页面结构

### 标题区

- 保留“当前企业福利机会”等动态标题。
- 标题右侧只显示当前结果数量，例如“72 条”。
- 删除现有四段状态按钮组。

### 统计摘要

- 五项指标固定为单行：当前有效、明确截止、公开预算、已核验、全部收录。
- 桌面端在一个低高度容器内等宽排列，使用细分隔线，不再出现第二行。
- 数字为主要视觉层级，标签为次要视觉层级。
- 移动端保持单行，通过横向滚动访问全部指标，不挤压成难读的小格子。

### 筛选栏

- 在现有筛选栏最左侧新增“机会阶段”。
- 选项固定为：当前机会、前置信号、历史续采、待核验线索。
- 其余筛选依次为商机类型、福利场景、地区、截止窗口、快捷筛选。
- 阶段变化沿用现有 API 路径和数据源，不改变机会分类规则。

## 交互规则

- 默认阶段为“当前机会”。
- 切换阶段后同步更新标题、结果数量、统计摘要和分页。
- “待核验线索”继续读取候选线索 API；其他阶段读取公开机会 API。
- 切换阶段时页码回到第一页。
- 浏览器刷新后仍使用默认阶段，不新增本地持久化状态。

## 响应式与可访问性

- 所有筛选项必须有可见标签。
- 阶段选择器使用原生 `select`，支持键盘和移动端系统选择器。
- 统计摘要容器在窄屏允许横向滚动，并保留清晰的焦点与文本对比度。
- 不改变当前商务生活方式配色、字体和卡片风格。

## 验收标准

1. 桌面端五项统计在同一行，没有“全部收录”掉到第二行。
2. 原四段状态按钮组完全移除。
3. 筛选栏第一项为“机会阶段”，四个阶段均可切换。
4. 阶段切换会改变标题和机会内容，并重置分页。
5. 当前机会、历史续采、前置信号和待核验线索均能正常返回。
6. 移动端统计摘要可用且不发生文字重叠。
7. 福利页面专项测试、类型检查、V1.5 E2E 和远程 smoke 全部通过。

## 范围边界

- 不修改机会采集、分类、证据或销售跟进逻辑。
- 不重做机会卡片。
- 不修改主站、AI Events 或其他雷达页面。
