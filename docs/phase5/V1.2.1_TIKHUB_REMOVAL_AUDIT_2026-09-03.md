## Finance Radar call sites after

After the removal commits:

```text
Finance Radar runtime TikHub calls: 0
Finance Radar scheduler TikHub calls: 0
Finance Radar manual/golden test TikHub calls: 0
Finance Radar company-enrichment TikHub calls: 0
```

`company-enrichment.ts` now accepts only a generic allowed company-profile
provider contract and rejects unknown provider identities before invoking a
provider. The Finance Radar routing contract contains only Doubao, Serper,
and selective Exa routes. The no-TikHub verifier injects a fail-fast forbidden
provider and executes the weekly pipeline; the forbidden provider is never
called.

The word TikHub remains in this audit, historical reports, deployment notes,
and the explicit deny-list verifier. Those references are evidence and guard
rails, not provider registrations or API call sites.

## Remaining TikHub code outside Finance Radar

Historical TikHub benchmark scripts and raw evidence may exist in the prior
pre-move ChancePing checkout and in archived benchmark artifacts. They are
not imported by the current Finance Radar build, scheduler, manual weekly
entrypoint, or production smoke path. They are retained as immutable historical
evidence only and are not executed by V1.2.1.

The current Finance Radar checkout has no LinkedIn/TikHub benchmark module in
its runtime source tree. Any historical benchmark invocation is explicitly
outside this product path and is prohibited during this hotfix.

## Boundary and conclusion

This audit does not delete historical raw evidence and does not claim that old
TikHub spend was zero. It proves the narrower required invariant:

```text
V1.2.1 Finance Radar TikHub API calls = 0
```

Historical spend is audited separately by
`scripts/audit-tikhub-spend.ts`, using read-only artifact inspection only.
