# DS2 真实来源适配与只读发现设计 V1.0

## 1. 阶段边界

DS2 只负责把 DS1-B 的候选适配器变成可重复的只读发现运行：记录来源级状态、列表页快照哈希、候选数、详情页快照哈希和失败原因。DS2 不写正式机会库，不改变公开数据，不执行导入或部署。

## 2. 运行契约

每次运行必须包含：

- `run_id`、开始/结束时间；
- `source_runs[]`：来源 ID、适配器 ID、发现入口、访问模式、HTTP 状态、最终 URL、列表快照哈希、候选数、候选样本和错误列表；
- 每个候选的详情页 URL、字段 provenance、`candidate_only` 状态和详情快照哈希；
- `formal_store_before_sha256`，用于证明正式库未被运行改变；
- `readonly=true`、`formal_store_write=false`。

## 3. 当前适配范围

首轮运行 3 个来源：

1. 中国政府采购网地方公告；
2. 广东省文化和旅游厅通知公告；
3. 广州市越秀区人民政府通知公告。

每个来源最多读取 3 个详情页，异常只记录，不绕过反爬、不登录、不提交表单。

## 4. 进入/退出门禁

进入 DS2：DS1-A 至 C 的来源端点、样本适配器和候选审计记录可追溯。退出 DS2：每个来源都有运行记录和快照哈希，候选仍保持 `candidate_only`，正式库哈希不变；失败来源进入 DS2 后续适配队列。
