# DS5 规模化运营与持续优化设计 V1.0

DS5 建立来源注册、只读发现、候选质量、人工审核和受控晋级的周期性运行闭环。默认建议每 3 天运行一次；临近截止机会按来源策略提高复核频率。运行账本只记录来源频率、上游门禁、正式库快照和下次运行时间，不在发现阶段写正式机会库。

## 运行顺序

```text
来源端点/健康核验 → DS2 只读发现 → DS3 质量分层 → DS4 正式库审计 → DS1-D 审批包 → 单批受控导入 → API/SSR/回归 → 新基线
```

## 持续优化规则

1. 来源健康失败先降级或标记待复核，不以数量替代可信度。
2. 同一机会以具体第一方详情页为主来源，聚合页只作为发现线索。
3. 未确认字段保持 `null` 或明确未确认文本。
4. 任何正式写入都需要批次号、前后快照、审计记录和可恢复备份。
5. DS2/DS3 必须保持只读；发现与质量脚本不得绕过 DS1-D。

脚本：`npm run ich:ds5:operations-audit`；验证：`npm run verify:ich:ds5`。
