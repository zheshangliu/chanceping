# 非遗机会雷达 DS1：来源注册与采集设计 V1.0

## 1. 阶段边界

本阶段只完成来源注册、采集契约和质量门禁设计，不执行真实抓取、不导入新机会、不修改生产机会库、不发布新增机会。

DS0 已经建立模板污染检测和发布阻断。DS1 的所有采集器必须先经过候选模式验证，不能绕过 DS0 语义一致性校验。

## 2. 当前问题

旧来源体系存在三种对象混用：

1. 来源网址目录；
2. 人工发现候选来源；
3. 已具备稳定采集能力的生产来源。

因此，来源列表数量不能代表真实覆盖能力。DS1 使用独立的 `source-registry.v2.json`，为每个来源补充来源角色、证据等级、地区、分类、查询包、访问模式、扫描频率、复核频率和运行状态。

旧版 [source-registry.json](/Users/1sunflower/Documents/chanceping/src/ich/source-registry.json) 保留作为兼容目录，DS1 不直接覆盖它。

## 3. 来源分层

| 层级 | 角色 | 允许用途 | 典型来源 |
|---|---|---|---|
| S1 | `primary` | 可回溯到具体官方详情页，满足条件后可进入正式机会 | 政府公告、政府采购、公共资源交易、官方机构项目页 |
| S2 | `secondary` | 主办方、协会、博物馆和展会机构，需核对具体项目页 | 工艺美术协会、非遗馆、博物馆、展会主办方 |
| S3 | `discovery` | 只产生线索，不能直接作为正式机会来源 | ASEF、Res Artis、TransArtists 等聚合平台 |

来源等级与机会等级分开：来源登记为 L1/L2/L3，不代表从该来源发现的每一条机会自动拥有相同等级。

## 6. 采集器契约

每个来源适配器必须声明：

```text
source_id
access_mode
discovery_url
query_pack_ids
pagination_strategy
request_timeout
raw_snapshot_hash
extracted_fields
field_provenance
candidate_count
failed_reason
```

允许的访问模式：

- `listing`：栏目列表页和详情页；
- `search`：站内搜索或政府采购查询；
- `rss`：官方 RSS；
- `sitemap`：官方站点地图；
- `manual`：只能人工核验的来源。

没有稳定列表或搜索入口的来源只能处于 `discovery_only` 或 `manual`，不得假装已接入自动采集。

## 7. 发现、审核和发布边界

```text
来源扫描
  → 原始页面快照
  → 候选标题和链接
  → 字段提取及逐字段 provenance
  → DS0 语义完整性检查
  → 去重和状态计算
  → 人工审核
  → 正式机会库
```

正式发布至少需要：

1. 具体机会详情页，不接受只有首页的链接；
2. 唯一主来源；
3. 标题、主办方、地区和分类相互一致；
4. 截止日期或明确长期项目证据；
5. 未确认字段保持 `null` 或“未确认”；
6. 通过 DS0 语义校验；
7. 对国际基金、驻留和交流项目提取申请主体限制。

聚合平台只能帮助发现，正式记录必须回溯到第一方主办方页面。

## 8. 扫描与复核频率

| 来源类型 | 发现频率 | 临近截止复核 |
|---|---|---|
| 政府采购和公共资源交易 | 每天 | D-14 起每3天，D-7 起每天 |
| 广州、广东政府公告 | 每天 | D-14 起每3天，D-7 起每天 |
| 赛事、展会、协会 | 每3天 | D-14 起每3天 |
| 国际聚合和驻留目录 | 每3天 | D-14 起每3天 |
| 年度基金和长期项目 | 每周 | 发现新公告时立即复核 |

## 9. DS1 分阶段执行

### DS1-A：来源端点核验

只读确认每个 `canonical_url`、列表页、搜索页和分页策略，记录 HTTP 状态、最终 URL、页面类型和是否需要 JavaScript。

验收：首批31个来源均有端点状态，不把首页直接当作机会详情页。

### DS1-B：首批采集器样本

优先实现采购和广州/广东来源，使用固定样本测试提取标题、主办方、截止日期、地区和原始 URL。

验收：每个适配器至少有3个真实页面样本，候选模式运行，不写正式库。

### DS1-C：候选审计

把采集结果输出为候选文件，执行去重、状态、地区、来源等级和 DS0 语义审计。

验收：候选中没有模板污染；缺字段不被补猜；聚合来源均有回溯链接。

### DS1-D：受控发布

只有 DS1-A 至 C 通过后，才允许将少量候选导入正式机会库，首轮不超过10条，并保留完整运行记录。

## 10. DS1 完成标准

- V2 注册表通过结构校验；
- 31个核心来源有明确角色和分类；
- 六类机会均至少有一个来源池；
- 采购类来源不少于5个；
- 广州/大湾区来源不少于5个；
- S3 发现来源与 S1/S2 正式来源明确区分；
- 所有来源均有扫描频率和复核频率；
- 采集器契约要求原始快照和字段 provenance；
- 尚未通过端点核验的来源保持 `planned`，不宣称已自动采集。
